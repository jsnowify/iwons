Checkbox and switch styling is maintained in `src/styles/checkboxes.css`, imported once by `src/app/globals.css`. Use a native `<input type="checkbox">`; the shared style applies automatically. Use `<input type="checkbox" role="switch">` for an on/off switch. Keep each input inside a label or connect its label with `htmlFor`. Checked, indeterminate, disabled, keyboard-focus, light/dark, and forced-color states are handled centrally using existing tokens. No JavaScript is needed for styling, and the controls retain their native form and keyboard behavior.

The source scan found 11 checkbox inputs across seven application components: settings (five), onboarding consent, Path free browse, list selection, problem bookmarking, the embedded visualizer, and the main visualizer's Predict step switch. Settings preferences, Path free browse, and both visualizer prediction controls use the shared switch variant. Consent, list selection, and bookmarking use the shared square checkbox. All use the global stylesheet; the visualizer no longer carries a separate switch appearance. `/design/` includes interactive examples of the shared states for future review.

`e2e/checkboxes.spec.ts` checks keyboard interaction, disabled/mixed states, theme variants, forced-color fallback, and saved settings at phone and desktop sizes. `e2e/visualizer-controls.spec.ts` checks control alignment and the Predict step switch at six widths, including the completed/reversed-array state from the reported screenshot.
