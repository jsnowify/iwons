## Findings (1 and 2 historical; 3 open)

1. **P2 - Wrong source-line labels in the execution-order trace.** `lessons/how-code-runs.json:346` (Python), `:570` (JavaScript), `:794` (TypeScript) label the final snapshot as line 1 even though its message and state show the second statement has run. This teaches the wrong mapping precisely when learners are learning to follow source order. Use each track's second statement line for that snapshot. The same defect exists in the mirrored lesson.

2. **P2 - Input trace points at output while asking the learner to perform input.** `lessons/the-input-desk.json:113` (Java), `:335` (Python), `:557` (JS), `:779` (TS) show line 6/2, the output statement, with “Read the supplied line before printing.” The next snapshot immediately combines the stored name and completed greeting. Use read-line labels (Java 5, others 1), show stored-name/empty-output state, then advance to the print line. This is especially useful because names and joining strings are new supplied concepts in this lesson.

3. **P2 - Correct symbol-name answers are rejected.** `lessons/reading-a-program.json:227` and the corresponding card in every track ask for the symbol name in “A quoted string ends with a closing ___.” `keys/reading-a-program.json:38` and repeated keys accept only `quote`. “quotation mark” and “quote mark” are valid completions, but exact RecallCard matching marks them wrong. Add accepted alternatives or make this multiple choice. Actual output questions should retain case/space-sensitive matching; natural-language terminology should not penalize equivalent terminology.

## First-year concept order and correctness

The sequence output -> straight-line order -> message/punctuation distinction -> supplied line input is understandable. Strings and output are explained before use; the two-statement lesson restricts its top-to-bottom claim to straight-line code. The punctuation lesson repeats part of lesson 1, but adds a useful distinction between wrong output and source failure. Input introduces identifiers, declaration/type syntax and text joining together; labeling reading setup as supplied and deferring declaration details is reasonable if the trace accurately shows its role and the joining operator is explained.

Reference strings and checkpoint keys align with the statements by inspection. ## Required learner-experience answers

**Would a first-year learner stay engaged?** The desk-sign setting, immediately visible programs, small edits and later personalized greeting provide a clear reason to act. The later greeting changes the task meaningfully. Four lessons with the same seven-stage structure and repeated remove-a-quote experiments may become predictable, especially the first and third output lessons. This is a reasoned design assessment, not a measured outcome.

**Do interactions teach distinct things?** Prediction and running compare a mental model with observation; the two-line trace/Parsons task teaches order; the punctuation repair distinguishes valid wrong text from invalid source; the input ladder introduces fixed versus received text. The quoted-message trace exercise is effectively another output prediction, so its distinct value is limited. The input trace needs the intermediate stored-name state identified above to teach its advertised distinction.

**Which screens feel passive/repetitive?** First-message worked examples reveal/repeat a single print result; lesson 3 again predicts and edits one quoted string; all non-input break-it prompts remove the same quote; several recall cards repeat text already visible in traces. Shared Make paragraphs repeat Modify instructions before linking exercises. Trim these repetitions or give each screen a new decision rather than adding prose to meet a word target.

**Does each feedback item give a next step?** The inspected lesson answer objects, exercise explanations and five checkpoint explanations contain a next-step action. Checkpoint input/repair feedback is particularly concrete. Several lesson fill/trace explanations are generic templates that do not explain the learner's actual miss; they meet the structural requirement while falling short of consistently useful feedback. Fix the ambiguous quote key and replace template filler before calling feedback complete.
